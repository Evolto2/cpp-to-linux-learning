# 03 TCP 回显客户端与服务端

## 学习前提与来源

这是第三阶段材料，适合在掌握类、引用、string、数组、函数和基本 Linux 命令后学习。接触服务端时还需要了解线程和 std::move。

代码取自 [chriskohlhoff/asio](https://github.com/chriskohlhoff/asio)，许可证为 Boost Software License 1.0。这里只收录官方阻塞式 echo 客户端、服务端及完整 include 目录，源文件原样保留，不要求阅读整个网络库。

官方服务端对每个连接启动一个线程。这里的“阻塞式”是指连接中的读写方式，不代表程序没有线程，也不是生产级服务器示范。

## Windows 两个终端运行

先在仓库根目录执行 `scripts/build-windows.ps1`。然后打开两个 PowerShell 终端，两个终端都进入仓库根目录。

终端 A：

```powershell
Set-Location -LiteralPath 'C:\Projects\cpp-to-linux-learning'
& '.\build\windows\tcp_echo_server.exe' 19081
```

服务端等待连接时没有提示输出，这是原版行为。终端 B：

```powershell
Set-Location -LiteralPath 'C:\Projects\cpp-to-linux-learning'
& '.\build\windows\tcp_echo_client.exe' 127.0.0.1 19081
```

在 B 输入 `hello` 并回车，预期出现 `Reply is: hello`。原客户端收发一次就退出，A 继续等待下一次连接；结束 A 使用 Ctrl+C。

`127.0.0.1` 表示本机，19081 是这次示例端口。客户端和服务端必须使用相同端口。官方服务端使用 IPv4 通配地址监听，示例命令与本轮检查都只连接本机，不要据此认为它只监听回环地址。

## Linux 对应命令

在仓库根目录执行：

```bash
bash scripts/build-linux.sh
./build/linux/tcp_echo_server 19081
```

另开一个终端，进入同一仓库根目录：

```bash
./build/linux/tcp_echo_client 127.0.0.1 19081
```

依赖 C++17 编译器、CMake、Make 和线程支持；Asio 头文件已随仓库提供。Windows 通过构建文件链接系统网络库，不需要自行下载 DLL。

## 阅读顺序

1. 先读 `upstream/src/examples/cpp11/echo/blocking_tcp_echo_client.cpp`：检查参数 → 建立 socket → 解析地址并连接 → 读取键盘输入 → 写出请求 → 按请求长度读回响应。
2. 再读服务端同目录的 `blocking_tcp_echo_server.cpp`：监听端口 → accept 接受连接 → 启动 session → read_some 读取一段 → write 回传相同字节。
3. 最后理解 std::thread、std::move 和 socket 生命周期；不要先钻进 upstream/include 的实现。

TCP 传输的是字节流。客户端一次写入，并不保证服务端一次读完；read_some 可能只得到一部分，官方 session 循环会继续读取，asio::write 则负责写完给定缓冲区。

## 三个修改练习

从仓库根目录执行下面的命令建立练习副本；复制只执行一次，已有自己的修改后不要重新覆盖。

```powershell
New-Item -ItemType Directory -Force '.\practice\tcp-echo' | Out-Null
Copy-Item '.\projects\03-tcp-echo\upstream\src\examples\cpp11\echo\blocking_tcp_echo_*.cpp' '.\practice\tcp-echo'
```

修改并保存后，分别编译客户端和服务端；头文件仍使用仓库内的 Asio，Windows 链接系统网络库。

```powershell
clang++ -std=c++17 -DASIO_STANDALONE -D_WIN32_WINNT=0x0601 -I projects/03-tcp-echo/upstream/include practice/tcp-echo/blocking_tcp_echo_server.cpp -lws2_32 -lmswsock -o practice/tcp-echo/server.exe
clang++ -std=c++17 -DASIO_STANDALONE -D_WIN32_WINNT=0x0601 -I projects/03-tcp-echo/upstream/include practice/tcp-echo/blocking_tcp_echo_client.cpp -lws2_32 -lmswsock -o practice/tcp-echo/client.exe
```

两个终端分别运行 `.\practice\tcp-echo\server.exe 19081` 和 `.\practice\tcp-echo\client.exe 127.0.0.1 19081`，确认运行的是练习版本。

1. 连续收发：让客户端支持输入多行，约定输入 quit 后退出；验收为同一连接内连续收发三行，quit 的处理方式有明确说明，不能把一次 recv 当成一条完整消息。
2. 增加日志：显示连接、收发字节数和断开事件；验收为日志反映实际读写长度，中文消息按字节计数，不能用字符数替代。
3. 处理断开：在客户端等待响应时关闭服务端；验收为显示可理解的错误并退出，无无限等待，恢复服务端后新客户端仍可连接。

这里只给目标与验收，不提前提供答案。消息分界协议需要由练习代码明确约定，例如按换行分界；不要修改原版后仍称其为官方原始代码。

## 常见问题与原版边界

- Connection refused：先运行服务端，核对 IP 和端口。
- Address already in use：可能有其他进程使用该端口，先识别进程或换一个未占用端口，不关闭不明进程。
- 客户端输入最多容纳 1023 个字节，超长输入不会完整发送；服务端的循环本身可以回显更长的字节流。
- 原版参数解析较宽松，异常捕获后可能返回 0；不能只凭进程退出码判断通信成功，检查脚本还比较了实际回显内容。
- 原版服务端无限接受连接并分离线程，没有连接数限制和完善的优雅退出，不作为高并发、生产部署或性能结果。

掌握标准：能画出客户端和服务端的收发顺序，解释端口、连接、缓冲区与字节流，并完成一个小修改。
